# Chess Bet — шахматы на USDC (Polygon)

Игроки ставят от **0.05 до 5 USDC** (шаг 0.05), играют на время (15/30/45 мин, 1/3/24 ч). Победитель получает **90%** банка, **10%** уходит на кошелёк владельца проекта `0x6404abDeb8a95817282B5f171D046211Db549Bd6`. Выигрыш (или возврат ставки при ничьей) игрок забирает кнопкой «Забрать»: контракт переводит USDC на его кошелёк. Ничья, отмена и аварийный возврат — ставки возвращаются полностью. Есть игра с ботом без токенов (5/15/30/45 мин). Вход через кошелёк thirdweb, 9 языков (ru, en, es, de, fr, pt, tr, zh, ar с RTL).

> ⚠️ **Статус кода.** Код написан целиком, но в среде разработки не было доступа к npm, поэтому **контракт не компилировался, тесты не запускались, сборка Next.js не выполнялась**. Проверен только синтаксис TypeScript и совпадение переводов. Первым делом выполните шаги 1–3 ниже и исправьте возможные мелкие ошибки типов/версий.

## Запуск

Нужен Node.js 20+.

### 1. Контракт
```bash
cd contracts && npm install
cp .env.example .env        # заполните ORACLE_ADDRESS, DEPLOYER_PK
npx hardhat test            # все тесты должны пройти
npm run deploy:amoy         # тестнет (если USDC_AMOY пуст, задеплоится MockUSDC)
```
Затем mainnet: `npm run deploy:polygon`.
Адрес USDC на Polygon (нативный, Circle): `0x3c499c542cEF5E3811e1192ce70d8cC03d5c3359` — **сверьте на polygonscan.com и в документации Circle** перед деплоем.
Для Amoy: после деплоя MockUSDC вызовите `mint(игрок, сумма)` для тестовых игроков.

### 2. Сервер
```bash
cd server && npm install
cp .env.example .env        # RPC_URL, ESCROW, ORACLE_PK
npm start
```
`ORACLE_PK` — ключ отдельного кошелька (не owner), на нём нужен POL для газа (`reportResult` вызывается за каждую партию).

### 3. Веб
```bash
cd web && npm install       # postinstall копирует Stockfish в public/
cp .env.example .env.local  # NEXT_PUBLIC_THIRDWEB_CLIENT_ID, NEXT_PUBLIC_ESCROW, URL сервера
npm run dev
```
Client ID: https://thirdweb.com/team → ваш проект; добавьте домен приложения в разрешённые. В `NEXT_PUBLIC_CHAIN_ID` поставьте `80002` для Amoy.

## Как это работает

1. Игрок вызывает `createGame` (перед этим `approve` USDC — интерфейс делает это сам). Ставка блокируется в контракте.
2. Сервер читает события контракта (`GameCreated/Joined/Cancelled`) и раз в минуту сверяется с цепочкой, поэтому лобби всегда соответствует блокчейну.
3. Соперник вызывает `joinGame` → сервер создаёт партию. Белые — создатель.
4. Клиент подключается по WebSocket, сервер присылает одноразовый nonce, клиент подписывает сообщение кошельком. Ходы принимаются только от игрока, чей сейчас ход; сервер валидирует их через chess.js и ведёт часы.
5. По окончании сервер вызывает `reportResult` (с повторами при сбое): контракт записывает, сколько вправе забрать каждый игрок, а 10% комиссии сразу отправляет владельцу проекта. Клиент никогда не определяет победителя.
6. Победитель видит поздравление и кнопку «Забрать +X USDC» → транзакция `claim(id)` переводит выигрыш на его кошелёк. При ничьей кнопка есть у обоих. Невостребованные выплаты видны в «Профиль → Невостребованные выплаты».
7. Если сервер не сообщил результат, через `2 × время + 3 дня` любой вызывает `refundStuck` (кнопка «Вернуть ставки» в профиле, можно ввести номер игры), после чего оба игрока забирают ставки через `claim`.

**Почему «забрать», а не автоматическая отправка.** Если адрес игрока заблокирован в USDC (Circle умеет блокировать адреса), автоматический перевод ему сорвал бы расчёты по игре. При схеме claim каждый забирает свою часть независимо.

## Приглашения и приватные игры

- Любую свою игру можно отправить по ссылке `https://ваш-сайт/?game=15`: Telegram, WhatsApp, системное меню телефона или копирование. Открыв ссылку, соперник видит условия и кнопку «Принять».
- **Приватная игра** (галочка при создании) не показывается в общем лобби. Контракт хранит только адрес одноразового ключа; ключ лежит в ссылке после `#k=` и не уходит на сервер сайта. Присоединяющийся подписывает этим ключом **свой адрес и номер игры**, поэтому перехват транзакции другим игроком не позволяет занять место.
- «Профиль → Мои игры»: созданные и ожидающие соперника игры (поделиться / отменить), идущие партии (продолжить).

## Что есть в партии

- Таймер каждого игрока: у каждого свои отдельные минуты (например, 30), часы идут только на своём ходу, у кого время кончилось первым, тот проигрывает. **Часы запускаются только после первого хода белых** (сам первый ход время не расходует). Если белые не сделали первый ход за время партии (то есть за выбранные 15/30/45 мин, 1/3/24 ч после принятия вызова), партия отменяется и ставки возвращаются без комиссии.
- **Просрочка времени и недостаточный материал.** По правилам ФИДЕ, если у соперника просрочившего нет возможности поставить мат никакой серией ходов (один король, король и конь или слон против короля, слоны одного цвета), засчитывается ничья, а не победа. Проверка есть и на сервере, и в игре с ботом.
- Подсветка ходов, список ходов.
- Кнопки ⏮ ◀ ▶ ⏭ для просмотра сыгранных ходов; пока смотрите историю, ходить нельзя, «⏭» возвращает к текущей позиции.
- Победитель: поздравление с анимацией и кнопка «Забрать».
- Бот отвечает не раньше чем через 2 секунды после вашего хода.

## Перед запуском с реальными деньгами

- **Аудит контракта** независимой командой. Тесты в `contracts/test` покрывают основные ветки, но это не аудит.
- **Ключ oracle**: только в секретах сервера (не в git, не в логах). Тот, у кого ключ, решает исход любой партии. Рассмотрите отдельный кошелёк с минимальным POL, мониторинг и ротацию через `setOracle`.
- **Owner контракта**: передайте мультиподписи (Safe). Owner может менять oracle и комиссию (максимум 10% в коде).
- **Хранилище**: состояние партий сейчас в JSON-файле (`STATE_FILE`) с атомарной записью — подходит для одного экземпляра сервера. Для продакшена с нагрузкой перенесите в PostgreSQL/Redis и делайте резервные копии.
- **Сервер**: за reverse-proxy с TLS (`wss://`), задайте `ALLOWED_ORIGINS`, мониторинг и автоперезапуск.
- **Юридическая сторона**: ставки на деньги регулируются по-разному. Гео-блок: `BLOCKED_COUNTRIES` (по заголовку `CF-IPCountry` при Cloudflare) и/или на уровне хостинга. Замените шаблон `/terms` текстом от юриста.
- **Античит**: игра на деньги привлекает игроков с подсказками движка. Запланируйте анализ точности ходов и жалобы.

## Известные ограничения и что доделать

- Нет EIP-2612 permit (сейчас две транзакции: approve + createGame; approve пропускается, если allowance достаточен).
- Нет спонсирования газа (thirdweb Account Abstraction): у игрока должен быть POL.
- Подпись входа запрашивается при каждом переподключении WebSocket (для in-app кошельков тихо, для внешних появится окно). Можно добавить сессионный токен.
- Проверка подписи — для EOA-кошельков. Смарт-кошельки (EIP-1271) потребуют `verifySignature` от thirdweb на сервере.
- Часы белых идут с момента принятия вызова.
- Ничья по соглашению и по правилам (пат, повторение, недостаточный материал, 50 ходов) поддерживаются; отдельных ограничений на предложение ничьей нет.
- Звук хода — короткий сигнал WebAudio; настройки звука нет.
- Файл `web/app/terms/page.tsx` — шаблон.
- Ссылку на приватную игру можно получить только на том устройстве и в том браузере, где игра создана (ключ приглашения хранится в localStorage). Если очистить данные сайта, ссылку на уже созданную приватную игру восстановить нельзя; такую игру можно отменить и создать заново.
- Отдельного лимита времени на ход нет: у каждого игрока есть общее время на партию.
- Список «застрявших» партий для возврата строится по данным сервера; если сервер потерял состояние, используйте поле «Номер игры» в разделе «Вернуть ставки».
- Нужен `viem` (подтягивается через `npm install` в `web/`): он используется для подписи приглашений.
